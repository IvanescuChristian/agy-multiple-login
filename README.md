# agy Multiple Login

Adds a `--login_new <profile>` flag to the `agy` CLI (Google Antigravity) so
you can run a session under a different Google account, scoped to that one
invocation, without affecting any other running (or future) `agy` session.

## Why

`agy` keeps its sign-in and state under `$HOME/.gemini/`, shared by every
`agy` process of that user. Signing in as someone else replaces the login for
all of them.

## How it works

`bin/agy` is a small bash wrapper that:
- passes everything through unchanged to the real `agy` when no
  `--login_new` flag is given;
- with `--login_new <profile>`, runs that one invocation with `HOME` set to
  `$HOME/.agy-profiles/<profile>/`, so agy reads and writes its own private
  `.gemini/` there. The variable is passed only to that child process (never
  exported into your shell).

`HOME` is the only lever found: setting `ANTIGRAVITY_EXECUTABLE_DATA_DIR` was
tried and does NOT relocate the login.

### WARNING: `~/.gitconfig` and `~/.ssh` symlinks

Because the profile `HOME` is empty, git and ssh run by the agent would lose
their config. So on each launch the wrapper symlinks `~/.gitconfig` and
`~/.ssh` from your real home into the profile, only when they exist in the
real home and the profile has none. It never copies and never overwrites.

**Anything written under `~/.ssh` from inside a profile (for example
`known_hosts`, or a key generated by `ssh-keygen`) goes to your REAL
`~/.ssh`, and `git config --global` writes to your real `~/.gitconfig`.** If
you do not want that, delete the symlinks in the profile directory.

## Install

```sh
./install.sh                          # installs bin/agy to ~/.local/bin
./install.sh /some/dir                # or a custom directory
./install.sh --uninstall [dir]
```

The wrapper must come BEFORE the real `agy` on `PATH`. If the real `agy` is a
plain file at the target path (common: `~/.local/bin/agy`), the installer
refuses, because it would overwrite it. Use another directory instead:

```sh
mkdir -p ~/bin-wrappers && ./install.sh ~/bin-wrappers
export PATH="$HOME/bin-wrappers:$PATH"     # add to your shell startup file
```

The installer records the real binary's path in `<dir>/.agy-real-bin`, and
warns if `agy` on your `PATH` does not resolve to the wrapper.

## Usage

```sh
# First time: creates the profile and starts agy under it. Complete the
# interactive Google sign-in inside the session.
agy --login_new work

# Free sign-in check (no model call): lists models if signed in, otherwise
# says sign-in is required.
agy --login_new work models

# Later: reuses the saved login.
agy --login_new work

agy --login_new            # no name: list profiles
agy --login_new --list     # profiles and login status
agy --login_new --help
agy                        # no flag: the real agy, untouched
```

Profiles live under `$HOME/.agy-profiles/<name>/` (override the base with
`AGY_LOGIN_NEW_PROFILES_DIR`). Names may use letters, numbers, `.`, `_`, `-`.
`--list` reports "logged in" when
`.gemini/antigravity-cli/antigravity-oauth-token` exists in the profile.

## Limitations and what is NOT verified

- Bash only (Linux/macOS/WSL). No Windows port.
- Verified: under a scratch `HOME`, `agy models` reports sign-in required
  while the normal home lists models, i.e. `HOME` isolation takes effect.
- NOT VERIFIED: a completed sign-in persisting in a profile, and two
  different accounts running side by side (needs interactive logins).
- NOT VERIFIED: that `antigravity-oauth-token` is always the file agy writes
  on sign-in (inferred from the default layout); if `--list` says "not logged
  in" after signing in, trust `agy --login_new <profile> models` instead.
- NOT VERIFIED: resuming a conversation (`--conversation`) under a profile.
- Other dotfiles (e.g. `~/.npmrc`) are not linked into the profile.
- Use of multiple accounts is subject to the provider's terms of service.
